## 目标与可行性

建设经过验证的参考页面库，将相似页面检索、可复用布局及现有交付门禁结合起来，提高新建页面的结构和视觉稳定性。参考资源本身不能保证业务正确、美感或交付质量，必须通过确定性检查和人工审阅。

现有可复用基础：
- `src/services/ai/workflowSources.ts`：参考图实际输入及设计库来源校验。
- `src/services/ai/promptBuilder.ts`：生成上下文和设计规则组装。
- `src/services/ai/pageCreationValidation.ts`：源码、结构、资源、实体及实际iframe渲染验收。
- 现有候选、History、交付档案、参考设备和视觉回归链。

当前参考内容主要是通用工艺规则和组件说明，尚缺按页面用途检索的完整案例。技术接入难度预估中等，持续投入重点在母版制作、分类、适配和审核。此判断为方案分析，不是开发工期或效果承诺。

## 每条资源的内容

- 用途标签：页面类型、业务功能、设备档位、信息密度、适用和不适用场景。
- 截图、原生HTML及关键区块。
- 布局合同：主要区域、必需内容、主次操作、长文本规则及窄屏降级方式。
- 正常、空数据、加载、错误等适用状态。
- 来源地址、许可、版本和内容指纹。
- 参考设备、主题、渲染与人工审核记录。

完成适配和审核的资源进入可生成母版库；截图资料可单独保留为仅供视觉参考。

## 新建页面工作流

需求与项目文档 → 页面类型匹配 → 参考检索 → 母版复用或参考生成 → 项目Token适配 → 验收 → 候选采纳。

1. 综合功能、结构、设备和状态匹配，不能仅按页面名称。
2. 已有项目页面决定视觉语言，公共案例补充布局；既有Token及组件绑定继续决定实现。
3. 一次采用一个主参考，按需补充少量区块，控制上下文长度和风格冲突。
4. 匹配不足时显示暂无合适参考，可继续普通生成。
5. 已明确目标及修改细节的小改动，保持直接复制局部修改，不增加分析或整页套版。
6. 保存实际采用的来源、版本及输入记录，不能将未发送的参考图记为已使用。

建议入口为“资源中心→参考页面”；新建页面对话区提供“自动参考／手动选择／不使用”，显示所选资源用于结构还是风格，允许更换。

当前图片输入回执以单张参考图为主，首期可采用一张主图加结构说明。多图输入需要独立扩展，并保留用户原图来源及回执。

## 质量验证

| 对象 | 检查重点 |
|---|---|
| 参考母版 | Token、资源、设备渲染、长文案、长按钮、角标及状态样例 |
| 生成结果 | 必需功能区域、主操作可见性、文案完整性、项目一致性和严重布局问题 |
| 实际效果 | 首轮通过率、人工盲评采纳率、返修次数、耗时及Token消耗 |

像素回归用于检查母版自身退化；生成页内容和主题允许变化，不能要求与参考图逐像素一致。现有门禁继续阻止不合格结果，视觉模型仅辅助审阅，人工确认负责最终审美判断。
