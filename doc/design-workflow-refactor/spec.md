# 设计流程稳定性重构规格

## 目标
把生成与修改从“拼接提示词后请求模型”提升为可追踪、可验收的设计任务流程。每轮任务必须在执行前明确操作类型、目标页面、修改范围、工程约束和验收条件；页面候选必须继续经过原有安全、完整性、Token、结构与动作检查，不能因流程重构绕开质量闸门。

## 范围
本阶段落地统一任务合同、工程清单校验和二级工作流来源追踪：
- 将 create / modify / element patch / theme / question 路由写成结构化 `DesignTaskContract`，作为 PipelineContext 与 PipelineOutput 的可追溯信息。
- 把目标设备、页面基线指纹、受保护节点、页面身份及验收条件注入 AI 上下文。
- 继续遵守单一目标裁决；明确修改元素时采用目标页面副本/候选，不重复要求宽泛分析；宽泛优化分析流程维持现状。
- 建立从现有工程状态派生的 Project Manifest 和校验器，避免另建与 `useProjectStore` 不一致的权威源。
- 将合同推广到 HTML 导入、单页润色和批量重塑；导入页元数据保留策略、设备、来源指纹和设计系统身份。
- 将设计系统来源（项目预设、HTML 导入提取、项目内编辑覆盖）纳入 ProjectData、History、项目保存/加载和后续生成/润色合同。
- 为项目组件库记录模板版本和提取来源；组件实例标记引用版本，工程清单报告缺失定义和落后实例。
- 页面跳转以画框 HTML 的 `data-target-screen-id` 为唯一持久化来源；检查器可编辑，画布 Shift+点击可预览跳转，工程清单检查失效目标并把有效关系纳入 AI 上下文。

后续阶段按本方案逐步扩展：页面关系编辑入口、页面状态/操作/导航完整性门禁、视觉渲染验收。不得宣称离线 DOM 检查等价于像素级视觉验收。

## 不变量
- AI 请求仍经 `aiService` Rust 代理；画框保持 `iframe srcdoc` 沙箱。
- 修改目标由 `resolveGenerationTarget` 裁决，下游只消费结果。
- 原页面通过候选并排呈现；任何质量失败均不得静默落盘。
- HTML 节点文本安全、Token 白名单、工程存储和 History 管道保持现有契约。
- 手机项目设备档位不可变，导航遵循项目自定义导航开关。

## 后续增量：表单交互契约
工程 Manifest 除平铺交互控件外，还应按 `<form>` 保留字段分组、字段名/类型/可访问名称/必填约束，以及提交动作。表单契约只表达 HTML 中可观察到的结构，不声称验证业务提交或角色权限运行态。外置 `form="id"` 的提交控件属于对应表单，不能误报为缺少提交动作。AI 上下文以有界摘要注入这些契约，降低修改表单时丢失字段和 CTA 的风险。

## 后续增量：视觉基准对比
提供可选的浏览器截图回归命令，输入实际 HTML、浏览器专属基准 PNG 和参考设备视口，生成实际截图、差异图及变化像素比例。页面脚本关闭以符合画框 CSP；不同浏览器必须使用各自基准；缺少浏览器、字体/图片未就绪、尺寸不匹配或差异超过阈值时不得报告通过。该命令属于人工评审辅助，不代替候选 iframe 渲染守卫。

安装可选依赖：`python3 -m pip install -r requirements-visual-regression.txt`，并运行 `python3 -m playwright install chromium webkit` 安装浏览器。先用 `--update-reference` 为指定浏览器建基准，之后在 CI/本机对比时省略该参数。每个基准应按浏览器、版本、操作系统和参考设备独立存放；仅当资源完整时才允许更新基准。

```bash
python3 scripts/compare-visual.py \
  --html ./screens/profile.html \
  --reference ./test/visual-baselines/chromium/mobile-390x844.png \
  --actual /tmp/profile.actual.png \
  --diff /tmp/profile.diff.png \
  --browser chromium --width 390 --height 844
```

## 运行态验收边界
画布 iframe 按 CSP 禁止页面脚本、表单网络提交及嵌套 frame；画布宿主会拦截普通点击，将其用于元素选择。因 PRD D7 明确排除可点击原型演示，本阶段只保证静态可观察契约（链接/目标、控件、表单字段与提交控件、可访问名称和引用完整性）以及实际 iframe 布局渲染结果。不得将这些静态信息描述为业务提交成功、角色权限正确或页面状态转移已验证。

如未来增加交互预览，应作为单独的 PRD 范围变更设计：默认隔离运行、不允许真实网络请求、与编辑画布分离，并为导航、表单结果和角色状态分别提供显式模拟定义及可重复验收用例。

## 完整方案续建：统一工作流与任务快照
设计工作流以代码目录声明 ID、优先级、需要的上下文、禁改范围与确定性校验器。主生成、导入和润色只选择目录中的工作流，不能再各自定义一套同名却不同义的执行边界。目录是运行时路由合同，不执行页面脚本，也不改变 PRD D7 的静态原型范围。

每次执行构建版本化任务快照，至少包含工作流、目标基线指纹、原始请求、实际注入的知识来源（文档/规则/决策/参考页面/设计系统及版本或指纹）、授权修改范围与受保护节点。生成期间使用快照；候选留存快照以便采纳前核对版本。文档被禁用、缺失或来源版本变化时必须可检测，不得继续当作当前知识。

采纳门禁还应核对设计系统来源的 `kind`、稳定来源 ID、来源内容指纹和 Token 版本。即使 Token 值未变化，切换来源也会使旧候选过期；仅分析、问答及主题建议的非画布工作流合同不得用于采纳页面候选。旧工程缺少来源字段时沿用原有 Token/渲染等门禁，不凭空推断设计库身份。来源核对不等于设计库模式已实现；只读引用、项目副本和编辑源库须有真实库实体与权限边界后才能开放。

项目副本模式以另一 `.aidesign` 工程作为本地来源：只读其 `project.json` 和被组件实际引用的资源文件，复制 Token、组件模板及这些图片/图标到当前工程；导入过程绝不写来源工程。来源与目标设备档位必须相同，组件模板引用的其他组件和本地资源必须在来源工程登记且文件存在。组件和资源 ID 按源工程命名空间映射，DOM 属性与组件内 CSS 路径同步改写，防止与目标工程冲突。资源文件先写入目标工程，失败时删除本轮新增文件并保持工程元数据不变；组件、资源登记和 Token 再作为一条 History 事务保存。撤销仅恢复工程记录，新写入的文件保留供重做引用。再次导入同源版本时，来源已删除的旧组件定义在目标工程保留，以免现有页面引用断裂。绑定身份、源指纹和版本进入工程文件与生成上下文。外部来源内容变更不会自动刷新当前副本，用户需重新导入。只读实时引用和编辑源库仍是未实现模式，不在界面中提供假选项。

候选持久化使用工程内独立的 `candidates/current.json`，记录项目 ID、候选 HTML、目标页面、任务快照与执行记录；它不进入 `project.json` 的页面清单或 History，也不写入会话 JSONL。每个项目只保留当前一份候选，顺序写入/删除防止慢写覆盖较新的丢弃操作。打开工程时只在项目 ID 和文件结构有效时恢复候选，渲染及资源文件检查一律从 pending 重新运行，旧检查结果不得作为采纳依据。若目标页、基线或知识/Token 已变更，候选仍可展示但必须由任务门禁阻断采纳。采纳、保留两版或丢弃均删除候选侧车。

候选资源门禁核对最终候选页面使用的全部工程内图片和图标，包括原页面已有的引用。注册信息和文件存在性分开检查：未登记或不安全路径直接阻断；已登记资源通过工程存储逐文件确认，缺失、不可读取或核对尚未完成时，普通及强制采纳都不得执行。无关页面中未被候选使用的资源仍由项目级资源面板单独审计，不应阻断当前候选。

候选验证证据随 `candidates/current.json` 保存：包括检查时间、候选与上下文指纹、参考设备、Token/设计库身份、实际源码安全与静态质量报告、当前交付检查、真实 iframe 渲染报告，以及将候选代入后的全项目资源引用/物理文件审计。项目资源审计列明检查过的资源路径与发现的问题；其它页面的问题仅作为工程级提示，不阻断当前候选。证据面板可查看检查项和问题。重开工程读出的报告明确标为历史记录，既不填充当前渲染状态，也不代替本次文件核对。每次完成实际检查后重新生成当前证据，不接受模型自述为检查结果。此增量不包含截图或跨浏览器像素验收。

长期交付记录保存于 `deliveries/screen-{hash}/{delivery-id}.json`。记录包含采纳方式、来源/结果页面、修改前后 HTML/CSS、原始请求和执行/验收快照，以及当时的设备、Token 和手动覆盖。采纳先重新核对引用文件并原子写入准备记录，再重新校验当前候选与工程上下文，最后经原有 History 管道修改页面并标记档案为已应用。准备记录写入失败不得修改原页；等待期间取消、切工程或基线变化则记录为已取消，禁止延迟应用。收尾写入失败时保留准备记录并明确显示状态待确认，不假称已归档成功。交付历史独立于当前页面可撤销状态；页面后来改变或撤销时，通过内容指纹标示与交付版本是否一致。页面级属性面板可查看记录及历史验收证据，损坏文件单独提示，不阻止其它记录读取。

资源完整性分两层：同步的工程清单识别 HTML、CSS 中的本地 `assets/images|icons/` 引用及显式资源 ID 是否登记（导入字体另由导入资源管道管理）；异步文件核对使用当前工程的 `ProjectStorage.exists`，不得将“登记了路径”误报为“文件真实存在”。候选采纳需阻止相对原页新增的缺失登记引用，导入确认需在资源落盘后复核文件存在。旧工程现存缺陷不应使无关局部修改全部无法采纳；交付报告后续接入。

页面静态分类存于 `Screen.metadata`，包含分组、设计状态、适用角色和候选来源页面 ID；Manifest 只从当前屏幕实体派生，报告候选来源断链。用户在检查器编辑分类必须进入 History；两版保留时自动登记来源页。分类进入项目上下文和知识版本指纹，但不驱动运行时权限、导航或状态机。

旧工程可在检查器按需运行全项目资源核对，展示未登记引用和物理缺失文件；扫描仅使用当前工程存储层，不通过外部网络猜测资源。结果只代表该次检查，跨工程切换或面板卸载时丢弃迟到结果。

候选交付状态不得由模型自行声称；必须从当前候选的任务快照、HTML 安全、静态质量、资源引用、新增资源物理文件与 iframe 渲染六项检查计算，并与画布及聊天候选卡的普通采纳按钮使用同一结果。新增已登记资源在文件核对完成前保持 pending，缺失或不可核对时阻断；原页面原有缺陷由项目资源核对另行报告，不阻断无关局部修改。报告有 `pending`、`blocked`、`ready` 三态，保留逐项消息用于定位原因。已有严重问题或缺失渲染证据不能显示为可采纳。结构守卫拦截后的显式强制放行只可跳过静态结构/文案质量项，仍须通过任务、HTML 安全、资源和当前渲染检查。

执行记录采用同一字段结构：来源、原始模型响应、已确认完整的 HTML、结束原因、实际续写次数、错误、警告和质量报告。主聊天及润色调用共享有界续写器；导入转换记录确定性 HTML 产物。局部 DOM 修改记录最终页面、质量报告、模式、实际目标节点与操作数；由于结构化模型应答不经过流式文本收集，原始响应字段留空，不能伪称已经保存原始模型文本。记录只是结果合同，不能以记录字段替代实际质量和渲染门禁。

宽泛修改走目录中的 `review-page-modification` 分析工作流，其合同没有授权 HTML 改动；建议按 JSON Schema 验证后才供用户选择。明确元素和具体改法进入 `edit-element-copy`，不重新分析。分析结果和后续候选分别持有各自合同，便于审计“分析”与“执行”之间的授权边界。

## 验收
- 每个 PipelineOutput 都可读到本轮工作流 ID、目标/参考页面、设备、基线指纹和验收清单。
- 模型提示明确任务范围与验收条件，但不允许覆盖用户已确认范围或工程安全约束。
- 对所有输出状态，合同均可追踪；问题回答、主题提议等非 HTML 路径也有合同。
- Manifest 校验能发现重复页面/资源 ID、无效设备配置、非法页面坐标与无效/重复交互目标（当关系数据存在时）。
- HTML 导入三种策略和润色候选都有可检查的工作流来源；设计系统来源随项目持久化且主题替换可撤销/重做。
- 组件模板修改时版本单调递增；实例同步会更新版本标记，跳过同步的旧实例可在工程清单中识别。
- 页面跳转目标必须是存在的工程页面；设置、清除都可通过 History 撤销/重做。
- 现有生成、修改、局部修改、宽泛分析、导入和重塑流程回归通过。

### 交付版本首屏预览归档（2026-10-23 增量）
采纳时复用真实 PNG 导出链路，以当时参考设备、Token、导入元数据和 L4 覆盖生成交付版本首屏图。预览为历史视觉快照，不代替 iframe 门禁或像素一致性验收。图像作为独立 PNG 二进制写入 `assets/images/delivery-preview-{id}.png`，JSON 仅保存路径、时间、引擎、尺寸、HTML/上下文指纹及失败原因。记录图片缺失或解码失败须明确提示，不用占位示意图冒充截图。
截图过程有时间、像素和字节上限；失败保留代码与检查档案，允许已通过现有门禁的候选按原流程采纳。采纳期间的取消、工程切换和上下文变化仍需阻止迟到应用。档案准备失败时清理未引用图片，准备成功后图片随历史事件保留（包括取消和撤销）。历史记录没有预览字段时显示未存档。交付前后页面快照补存渲染必要的 metadata；保留两版时复制原页 L4 覆盖并与新页面一起进入单次 History 事务，避免候选与实际保留版本样式漂移。尚未采纳候选的预览侧车留待后续接入。

### 未采纳候选首屏预览（2026-10-23）
候选获得当前上下文的真实 iframe 完成报告后，后台生成首屏 PNG，不阻塞现有采纳门禁。复用交付预览的设备、Token、导入元数据、L4 和本地资源渲染及大小/超时限制；失败明确展示，可主动重试，同一候选/上下文不会因重复报告无限重截。PNG 写入独立 `assets/images/candidate-preview-{candidateId}-{captureId}.png`，候选侧车仅保存状态、路径、尺寸、引擎、时间、候选及上下文指纹。
重新打开工程时可查看存档图片，但它仅为历史外观，不填充 live 渲染/资源检查，不满足采纳门禁；当前设备、页面、Token、覆盖或资源路径变化后按新上下文重跑。候选渲染身份补含目标页面的渲染 metadata，避免导航标题或导入模式变化误沿用旧图。旧图与当前上下文不同须明确标记。预览侧车和实际检查记录按同一候选串行保存，重试、切工程、新候选、丢弃和采纳期间的迟到结果不可复活侧车或覆盖新图。
当前侧车至多引用一张预览。成功替换图片、丢弃、替换候选及采纳后，按安全路径清理已失去引用的候选图片；交付档案有独立图片，不引用会被清理的临时图。预览二进制先写、侧车原子写后换引用；写失败清理新图，保留可重试状态。图片缺失、损坏、读失败不隐藏代码和验收记录。后台截图不改变页面、工程设置或 History。

### 模型 HTML 终结与重塑编排统一（2026-10-23）
主 Pipeline 与润色/批量重塑共用模型 HTML 完整性、源码安全、导航规范化和静态质量终结函数；网络/取消错误优先于残留 HTML，完整性检查先于 DOMParser 规范化。各流程仍保留自身结构授权语义（主流程允许用户明确授权的结构调整，纯润色严格保留原树），不能为了合并入口放宽守卫。局部结构化编辑维持现有 DOM 安全管道，本批不宣称已统一所有执行入口。
润色目标执行从 React 面板移入服务，输出合同/实际模型响应/结束原因/续写次数/质量报告与错误一致；确定性局部润色补执行记录。批量迭代也移入服务：冻结确认时的队列和试跑结果，试跑前后及每个请求/应用前核对项目快照，用户编辑、切工程、Token/覆盖/资源/文档变化或取消时停止，不覆盖迟到结果。取消不会继续发后续请求，已成功应用的项目历史保留。
