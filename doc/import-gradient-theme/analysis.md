# HTML导入与渐变主题诊断

2026-10-26，只读用户指定工程及应用实现。此文为诊断/建议，不表示渐变主题功能已实现。

## 工程事实

- 29个页面，26页带HTML导入记录，其中24页声明渐变（包含页面、按钮、卡片、头像和遮罩，不能把所有渐变都视为项目页面背景）。
- 当前主题背景浅色为#f7f4f3，surface为#ffffff，surfaceAlt为#f1edec。主色阶500为#ff8a55，语义主色浅色覆盖为#f57e4d。主题没有可存储渐变角度、色标、位置/尺寸的字段。
- 3个对话生成页没有直接声明gradient函数，但并非全无渐变：“完善资料弹窗”的一页用了bg-ambient-warm，“TA的主页·未登录浏览”用了bg-gradient-soft。后者按灰白surfaceAlt/surface生成渐变，未继承导入页暖橙色的参数；另一“完善资料弹窗”未使用渐变类。因此问题是主题/页面风格未贯通，不能声称浏览器不支持或三个生成页完全没有背景。
- 例：导入“编辑资料”有180度的#fff3ea到#f5f5f5头部渐变；“喜欢我的人”不同状态有粉/橙多色和背景遮罩，语义不同，不能自动全工程套用同一个装饰渐变。

## 链路问题

1. DesignSystemTokens.colors.background是ModePair纯色，颜色编辑和语义颜色解析依赖它为颜色值；直接写入linear-gradient会使background-color及对比度计算失效。
2. base.css已有bg-gradient-soft/bg-ambient-warm/bg-ambient-cool，参数由现有纯色角色决定，不是从参考页面提取的可配置渐变。
3. analyzeHtmlImport只通过opaqueColor提取body/html的纯色背景，无法保存背景图层、角度、色标和应用区域；页根容器/伪元素渐变也没有成为候选主题字段。
4. preserve保留页面自己的样式；unify会对不确定的复杂渐变保留原表达式，避免视觉被破坏，但这不等于更新项目主题。
5. HtmlImportDialog的useExtracted要求empty，因此有页面的工程不能在导入时选择从该页更新主题。

## 推荐方案

保留colors.background作为纯色回退，增加独立、分明暗模式的语义背景定义：page、primaryAction、decorativeSurface。渐变以结构化类型记录类型/方向/色标/透明度/位置及来源，编译为权威CSS变量和白名单类；不将任意CSS塞进颜色Token。

导入分析按页面根容器、可见面积和组件用途识别：纯色、页面渐变、主按钮、局部装饰、照片遮罩分开。解析CSS变量和明确层叠关系；遇到动态/复杂表达式，标明来源和置信度，保留源页，允许用户选取参考区域，不能猜一个颜色或自动提升为全局背景。

导入弹窗展示“当前主题/检测风格”的预览、差异、来源区域和受影响范围；默认仅保留本页，可勾选只提取“页面背景渐变”“主按钮渐变”或其他已支持的主题项。允许已有工程更新选中项，避免整套主题覆盖字体、半径、主色等无关设置；固定设计库引用仍需遵守只读/项目副本规则。

用户确认后，通过同一次History事务写入来源和主题版本。新建页默认继承项目page背景；整页或局部修改保持明确授权，不能因主题变化擅自重写所有旧页。旧页同步单独给出受影响页面列表/预览和选择。生成Prompt注入语义角色及实际参数，校验器在用户要求继承时检查是否被根部纯色遮盖，画布、HTML、PNG导出共用同一编译结果。

已有工程增加“从已有页面提取风格”入口，供本工程选择合适的页面背景样本，无需重新导入所有页面。优先仅采纳共同背景及按钮角色，保留原页面的特殊状态与装饰。

## 验收建议

线性/径向、透明色标、CSS变量、多层渐变、局部伪元素、照片遮罩均有夹具；无法确定用途不得自动应用。空/已有项目、只读库、明暗模式、选择性合并/取消、撤销重做均覆盖。实际生成页在参考设备下核对computed background-image和像素，导入/画布/独立HTML/PNG保持一致。旧纯色主题迁移后行为不变。
