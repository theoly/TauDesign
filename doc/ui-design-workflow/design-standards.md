# UI 设计指南与规范

状态：下一轮实施依据。结合[现有实例指导](../ui-design-guidance/guide.md)、Refactoring UI、公开 Skill 静态分析及项目缺陷经验整理；新增条目是否已成为代码校验，以实施验收记录为准。

## 1. 如何理解一条规范

每条规则必须区分三件事：希望用户获得的设计结果、TauDesign 可用的实现方式、当前能验证的事实。

规则分为合同底线、可判定质量规则、设计建议。严重程度与检测能力分别记录：一个建议即使很重要，没有可靠检测也不能直接成为自动阻断器。指定设备、明确文案、保护范围等由任务合同决定，不可被普通场景规则改写。

默认规范适用于新生成页面和允许修改的范围。保真导入只执行其转换合同和既有阻断检查；新增美学规则默认作为诊断，不可自动改写来源，也不因来源不符合原生类名规范而一律拒绝。

## 2. 内容、业务与主次

| ID | 规则 | 实现与审阅 |
| --- | --- | --- |
| CT-01 | 先确定页面目标、核心信息和下一步，再选择布局和装饰 | 简表记录主目标、主要区域和主次操作；不先套壳再拼字段 |
| CT-02 | 用户明确文案、字段和操作形成内容义务 | 精确文本与允许等价表述分开；逐节点校验，不因图标出现就认为按钮有文案 |
| CT-03 | 事实、推断、示例分开 | 项目文档和已确认决定支持业务事实；无数据时用标明的示例，不编造合同权益 |
| CT-04 | 操作视觉权重服从当前任务 | 同一区域有主要焦点；重复列表可重复主操作，不机械要求整页一个按钮 |
| CT-05 | 状态服务业务，不堆砌演示 | 只呈现任务所需状态；同组互斥状态一致；旧页不借指导新增状态 |
| CT-06 | 空状态说明当前情况和可行下一步 | 无数据与加载失败区分；不虚构已经实现的后台行为 |

## 3. 布局、空间与文字韧性

| ID | 规则 | 实现与审阅 |
| --- | --- | --- |
| LY-01 | 主内容服从工程设备档位 | PC 使用最大宽度容器；移动主内容单列，紧凑数据可用合理横向分组 |
| LY-02 | 组内距离小于组间距离 | 标签靠所属输入，标题靠下方正文；Token 阶梯按设备/密度取值 |
| LY-03 | 内容宽度优先于栅格整齐 | 空间不足先减少列或整组换行，禁止将正文挤成逐字窄列 |
| LY-04 | 长正文拥有独立阅读空间 | 纵向内容卡、可收缩文本子项和自然高度；不能靠缩字、裁文案或横向滚动掩盖挤压 |
| LY-05 | 短标签整体换行，长文本按语义断行 | `.nowrap` 控制 flex，与文字 `.text-nowrap` 区分；URL/编号按需断行，正文不全局 break-all |
| LY-06 | 参考首屏不是整页高度 | 长页自然增长；只对明确全屏/弹层使用视口几何，避免重复 min-height 叠加空白 |
| LY-07 | 固定/吸底区域不遮内容 | 由当前设备、安全区和内容高度测量，按钮文案与最后一行仍可见 |
| LY-08 | 通过布局关系对齐 | 不用负边距、任意位移掩盖结构问题；先检查盒子、行高、SVG 留白和布局轴。合法角标附着、光学微调与已授权叠层可使用受控位移，不按属性名一律禁用 |

## 4. 排版与阅读

| ID | 规则 | 实现与审阅 |
| --- | --- | --- |
| TY-01 | 用字号、字重和对比共同建立层级 | 标题/正文/辅助三层即可起步；辅助信息不一律缩小到不可读 |
| TY-02 | 正文按设备档位，字号只从现有阶梯选择 | 当前移动正文 `.text-md`、PC `.text-sm`；长正文 `.leading-relaxed`，单行控件沿用基座行高 |
| TY-03 | 相邻混合字号按基线，图标按盒子居中 | 金额与单位可用 `.items-baseline`；不能将文字基线策略套到图标按钮 |
| TY-04 | 语义、视觉和对齐分别处理 | 保留标题语义与表单 label；段落左对齐，数值列右对齐，短控件可居中 |
| TY-05 | 适配中文、长姓名、职业及混合文本 | 不机械套英文 ch 字数和字距；姓名、职业与头像分层，不能挤为单字竖排 |
| TY-06 | 用户指定按钮文字完整 | 短操作默认单行；先留宽、缩短自拟文案或让操作组换行，不能擅改用户文案。空间仍不足时允许经验证的自然多行和自适应高度，不强制 nowrap 造成溢出或缩小字号 |

## 5. 色彩、渐变、材质与媒体

| ID | 规则 | 实现与审阅 |
| --- | --- | --- |
| CO-01 | 当前主题和颜色角色优先 | 页面、卡片、装饰、主操作分别取角色；已有主题渐变可正常使用 |
| CO-02 | 前景按实际承载背景选取 | 不写死白字/蓝链接；彩色底不机械套灰字，不通过整块透明度弱化文字 |
| CO-03 | 可读性先于柔和或装饰 | 延续当前正文/副文本 4.5:1、大字 3:1 的指导；算法不适用的图片/渐变标记复核，不能假通过 |
| CO-04 | 状态不是只有颜色 | 文字、图标或形状辅助；正常、重要和紧急用不同权重，不把所有数字标红 |
| CO-05 | 不以统一化抹掉必要差异 | 品牌、语义色及数据视觉各有角色；不机械要求所有元素同色或固定品牌色面积 |
| DP-01 | 用留白/表面区分，边框与阴影有目的 | 输入、选择和焦点边界仍可见；避免每层同时重边框、重阴影和渐变 |
| DP-02 | 阴影表达浮起层级 | 内容卡轻，菜单/弹层更高；用当前 Token，不硬编码光源和阴影 |
| MD-01 | 图标尺寸、笔画、留白一致 | 内联 SVG，合理 viewBox；更大展示面积先扩容器，不暴力放大小图标 |
| MD-02 | 图片比例稳定，裁切保护主体 | 媒体容器裁切，正文和控件不随图裁切；加载/失败保留稳定空间 |
| MD-03 | 图片/渐变上的文字按覆盖区域审阅 | 必要时使用 Token 遮罩或实底；不凭单一像素或纯色计算宣称整块可读 |

## 6. 组件合同

| ID | 组件 | 合同 |
| --- | --- | --- |
| CP-01 | 按钮/按钮组 | 主操作及合同要求的按钮有可见文案，图标居中，点击区域按设备；文字完整，空间不足时换行操作组。明确的纯图标返回/关闭/通知入口允许无可见文字，但须有可访问名称，不能借此把主 CTA 变成图标 |
| CP-02 | 通知角标 | 附着主图标右上、预留独立角区，不遮主体、不改为并排；点/数字/紧急按意义分级，溢出计数说明策略 |
| CP-03 | 标签/筛选 | 状态明确，文字可读，整项换行；不把文字裁切后仅靠无法操作的悬浮提示补全 |
| CP-04 | 人物信息 | 头像不挤压，姓名优先、职业/单位次级；成对人员分组各自稳定，窄空间允许组换行 |
| CP-05 | 表单 | 标签、帮助、错误归属明确；移动输入沿用触控合同；输入状态不能只靠颜色 |
| CP-06 | 列表/卡片 | 紧凑行与长正文卡分开；保留信息分组及操作层级，不能套 list-item 导致正文窄列 |
| CP-07 | 底部抽屉/弹层 | 主体、滚动区与底部操作区分开；基于真实视口处理位置，不把整屏高度重复加到页面流 |
| CP-08 | 图片卡/数据卡 | 媒体、标题、指标、解释和操作各有可用空间；同组视觉一致但不强求所有内容等高裁切 |

这些合同指导生成与验证，但新增判定器必须用正反例证明可靠；不能把“所有圆角必须等于一个数值”之类偏好升级为阻断。

## 7. 常见页面模式

以下是内容布局合同，不是下载的完整页面母版。只在新建或已授权重设计时用于规划；参考图已明确布局时尊重来源。

| 页面类型 | 核心分区 | 常见失败与防护 |
| --- | --- | --- |
| 工作台/看板 | 身份/提醒、主要指标、待办、日程、入口 | 不等权卡片海；指标与操作分组，角标不遮身份图标 |
| 筛选/列表 | 查询筛选、结果与摘要、行内操作、分页/空态 | 标签整项换行，长内容不被按钮压成窄列 |
| 详情/档案 | 主体身份、关键属性、业务分组、权限/状态、主操作 | 事实完整，不把所有字段做同样彩色卡片 |
| 表单/录入 | 分步或分组字段、帮助/错误、结果说明、提交 | 标签归属清晰，正文不变单字竖列，提交文案可见 |
| 套餐/充值 | 余额、方案、权益差异、说明与协议、确认 | 套餐保持可读宽度，渐变/选中底保真，价格不擅自编造 |
| 对话/建议 | 对话上下文、建议正文、来源/状态、复制/采纳 | 正文独占宽度，操作区可换行，记录时间与信息分层 |
| 设置/个人中心 | 身份、分组设置、状态、次级导航 | 字段和开关对应，弱化装饰但保持状态可见 |
| 空态/错误/弹层 | 当前情况、原因/帮助、下一步、关闭/返回 | 区分没有内容和加载失败；不保留大片无意义高度 |

## 8. 静态可访问性与运行态边界

可直接检查的静态项包括：控件有可识别名称；表单有 label/关联；状态不只靠颜色；图标语义适当；重要内容不被几何裁切。

真实键盘行为、表单提交、动态播报、手势与动画中断属于运行态能力。当前只设计静态页面时不新增脚本模拟这些功能，也不能把静态标签检查标为运行行为已验收。图表需明确单位、图例和数据来源；不能编造业务分析结论。

## 9. HTML 导入、导航与视口单位

- 原生生成只用权威基座类；导入来源 CSS 可通过现有 scopedCss/资产来源合同保留，不能因为私有类不在基座里就删除样式。
- CSS 转换必须理解变量、渐变、伪元素、媒体查询和级联顺序；不能用颜色字符串全局替换或清空 background-image 来完成统一主题。
- 保真、全部统一、选择性统一三种模式的授权不同；未映射或无法可靠识别的样式明确保留并告知。
- 页面提取出的主色/背景/梯度仅形成主题建议；用户选择后走主题/History 管道。既有项目不静默更新。
- 生成、导入、画布和导出共用现有视口解析，区分工程固定宽度、参考设备、业务可用高度和内容自然高度。
- 导入的 vh/vw、动态视口单位及 calc/变量表达式按既有 CSS 解析管道处理；不能用正则盲替换所有单位，更不能为消除空白直接删所有 min-height。
- 默认移动顶部状态与微信导航由画布/图片壳层提供，不写入业务 HTML、不双重预留顶部；自定义导航打开时处理对应业务导航。HTML/PNG 导出分别遵守当前壳层合同。

## 10. 从规则到检查的映射

| 例子 | 可用证据 | 处理方式 |
| --- | --- | --- |
| 指定按钮文案缺失/被隐藏 | 内容义务、DOM 文本、安全文本读取、实际几何 | 有可靠事实时阻断 |
| 长正文被挤压/裁切 | 原文与实际节点测量、设备快照 | 可靠严重问题阻断；边界布局警告并复核 |
| 图标角标遮挡 | 语义组件身份与相交面积/预留空间 | 具备足够身份和阈值证据才阻断，不能把所有合法叠层都判错 |
| 原主题渐变被替换 | Token/来源指纹及当前授权差异 | 未授权则阻断；主动改主题按主题任务验收 |
| 间距层级不够美观 | 规则建议、截图及人工判断 | 设计建议/人工复核，不伪装为确定错误 |
| 图片上文字难读 | 实际叠加截图、支持范围内的计算 | 可确认不可见则阻断，否则明确未验证/复核 |
| “页面是否需要重塑” | 绑定、来源 CSS 和保护预检 | 只给静态建议，不以未知类或导入身份直接宣称美观/丑陋 |

## 11. 新规则入库规范

必须具备稳定 ID、版本、生命周期、来源、适用任务/设备/组件、正反例、优先级、触发条件、允许实现、例外、验证能力和审阅记录。外部代码示例先转换为 TauDesign 支持的实现，不原样注入模型。

语义一致不代表样式唯一；同一目标可有多种合法实现。规则是否检索命中、是否实际注入、是否执行检查、检查是否通过分别记录，不合并为一个“已使用/已通过”徽标。
