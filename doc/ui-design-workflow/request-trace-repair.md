# 请求来源与受控修复继承

2026-10-31，M3-02/03 的增量实施，不扩大原任务完成计数。

目标：预算拒绝发生在请求回执创建之前；受控修复继承原任务已冻结的规则，不重新检索目录或读取已改变的全局开关。自动修复继续使用根任务账本，用户另行点击的候选修复明确为一次独立请求，不能冒充原生成任务尚有额度。

## 验收

- [x] Pipeline/重塑已有预算耗尽时，底层调用数与规则请求数均为零，既有成功请求不被改为失败。
- [x] 修复的父来源只读、与原合同一致，范围变化/损坏来源拒绝；有限 JSON 不混入 HTML 输出指令，不增大原消息字符预算。窗口不足时显式记录冻结规则的预算省略，不静默重选。
- [x] 修复消息实际包含的规则与修复回执一致，取消/失败不能变成通过；旧无规则记录不补造“已使用”。自动修复共享原根预算，手动单次修复保留现有独立额度。
- [x] 新记录经过运行时校验并可只读展示/序列化恢复；密钥和完整用户消息不写入回执。

2026-10-31 本切片通过。17项新增，全量2,504项/0失败；类型检查、生产构建及Chromium/WebKit移动端/PC全套通过。日志、两份CLI报告和609文件指纹见 [trace](./evidence/2026-10-31-trace/)，实际浏览器结果见 [trace-ui/result.json](./evidence/2026-10-31-trace-ui/result.json)。

- Pipeline和重塑先预留预算，再进入回执/真实活动监控；预算耗尽、关闭或预取消不产生模型回执。错误已发出的请求仍保留failed记录和保守额度，不退款。
- 自动创建和多页创建把原TaskBudget传入修复服务，保持原根时限/额度；手动候选修复沿用原界面的一次独立1,800额度，显式用户动作不冒充原任务自动续写。

- 修复记录的父绑定/选择指纹、实际输入规则、因空间省略规则和实际调用状态随新页证据/候选/交付档案保存；新页历史和候选实时采纳重新核对来源，坏记录不标通过。旧无来源记录继续只读，不补造规则依据。
