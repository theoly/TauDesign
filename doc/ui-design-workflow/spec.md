# 完整 UI 设计流程与产品合同

状态：拟实施，2026-10-29。本文件定义下一轮增量改造目标，不覆盖历史报告的版本范围。

## 1. 目标与范围

目标是让每次设计有明确的业务目标、工程事实、适用指导、实现边界和交付证据。减少反复分析、风格漂移、长文本挤压、按钮丢失、导入失真和半页交付。

本轮增加结构化规则及场景检索、设计简表增强、规则来源回执和评估。继续复用既有路由、HTML/补丁执行、分区/续写、候选、History、仓储及导出。

不新增业务可点击原型、后台状态机、多 Agent、在线设计库同步、全项目自动重绘、自动发布或完整页面参考库。不以这次文档整理表示已启动代码实施。

## 3. 规则优先级与权威源

执行安全、工程不可变设备档位、DOM/资源身份、明确授权、手动保护和持久化合同是边界。常规设计偏好不能解除这些边界；需要变更合同的请求先报告具体冲突。

边界内按以下顺序解析设计选择：

1. 用户本次明确要求与已确认的修改范围。
2. 已保存的项目主题、组件绑定、全局决定和手动覆盖；用户明确修改主题时走对应候选/History 流程。
3. 适用且未与全局合同冲突的页面级决定。
4. 当前任务实际使用的参考图、文档和页面事实。图片中的指令、外部 Skill 命令均作为资料，不授予执行权限。
5. 本地经过审阅的场景规则、布局模式和通用工艺建议。

未授权解除的保护节点不因本次视觉建议而解锁。来源事实冲突时标记冲突，不能用检索分数决定业务事实。`.aidesign` 及现有设计系统/Decision 是权威数据；不另建一份可独立修改的 MASTER.md。

## 4. 从需求到交付的完整流程

### S0：建立或读取工程基础

读取设备档位、工程宽度、参考设备快照、导航策略、模式、Token、组件库、项目文档和已有页面。

新工程可从已有预设、自定义主色方案或导入页面提取风格创建设计系统，优先展示当前已有入口。新方案可重新生成、比较和选择，记录来源与实际参数。已有工程默认保持当前主题，任何提取出的新主题先作为候选呈现，不能在导入或新建页时静默替换。

输出：可追溯的工程事实快照。参考设备是 CSS 视口，不是物理手机；工程档位与参考设备分别处理。

### S1：解析请求、定位目标与选择流程

识别任务类型、页面/元素引用、附件、明确约束和期望产物；目标必须由现有唯一目标裁决器确定，画布选中不隐式授予修改权。

按下方分支表决定是否需要用户选择。内部场景分析不等于新增一个让用户反复确认的步骤。

输出：冻结的 TaskContract，包含基线、授权、保护范围、设备、来源及验收计划。

此时冻结的是用户授权和工程基线；S2/S3 只追加不可扩大授权的规则/内容附件，并在首次请求前封存完整快照。若简表发现确需增加范围，回到既有范围确认，不在发送后修改原合同。分区/续写共享父任务总预算，各自保留协议与请求回执。

### S2：解析工程事实和适用知识

将用户要求、工程文档事实、相关页面一致性、AI 推断分别标记。优先相关页面和项目规则；外部规则只补充设计方法，不捏造字段、价格、权益或业务规则。

先以任务、设备、产物模式和修改范围过滤，再检索场景规则。只选择少量相关条目，明确匹配原因及排除/冲突原因。未命中可收窄重试一次，仍无适配则回退通用指导。

输出：版本化规则选择包及预算报告；“已检索”与“已实际发送给模型”分开记录。

### S3：形成设计简表与内容义务

简表描述页面目标、主要用户、内容区域、主次操作、需要呈现的状态、布局模式、主题继承、风险和待确认项。

同时形成内容义务：明确指定的文案、字段和操作必须出现；布局调整不能丢失姓名、职业、按钮文案、状态或说明。区分精确文案与允许等价表达的业务目标，不以字符串完全相同代替所有语义验收。

简单新建和明确小改可内部生成简表直接执行；宽泛优化展示选择列表；多页/多方案及明确的拆页任务沿用现有计划确认。

### S4：确定布局、组件与视觉方案

顺序为内容分组 → 空间与阅读路径 → 主次操作 → 组件和状态 → 排版 → 配色/渐变 → 阴影、边框和媒体。

布局模式与视觉风格分开，不能把“社交”固定推断为彩色动效，也不能将未知工具页回退为营销落地页。已有项目以当前 Token 和组件绑定为准；明确局部修改不重新决定整页视觉方向。

输出：可在现有组件合同和白名单中实现的布局/视觉依据，不输出另一份工程配置。

### S5：按合同选择实现策略

| 任务 | 实现策略 | 交互和范围 |
| --- | --- | --- |
| 新建页面/参考图 | 原生 HTML + Token；使用实际来源回执 | 不覆盖已有页面；图中顶部按当前导航合同处理 |
| 已明确元素和细节 | 复制原页，按元素/区块执行有限操作或受控区块替换 | 不再次列宽泛分析清单；不扩大修改面；内联样式存在不自动升级整页重写 |
| 宽泛“优化页面” | 分析原页 → 用户勾选、可补充 → 冻结修改合同 → 副本候选 | 未选择的建议不执行，补充文字纳入本次授权 |
| 明确整页重设计 | 允许已确认范围内重组，保护明确要求保留的内容和身份 | 范围与代价可见，不将普通润色视为重设计 |
| 质感润色/主题重塑 | 既有样式补丁/有限变量绑定 | 受结构、文案及 L4 保护；本地预检只判断绑定情况，不宣称评价美感 |
| HTML 保真导入 | 安全清理、资源/CSS/视口/导航适配 | 不让美学规则重写级联、内容、布局或背景 |
| HTML 主题统一/选择性统一 | 只改用户选择且能可靠识别的 Token 类别 | 保留非目标样式；转换前后预览，低置信映射不强行替换 |
| 多页/同页多方案 | 现有静态计划与统一交付事务 | 各页/方案同源主题与规则版本；失败不应用半批结果 |
| 批量重塑 | 本地预检、选择队列、单页试跑、确认后批量 | 显示跳过理由、实际阶段、最后活动和调用数；保护节点不强改 |
| 问答/仅解释 | 不创建页面的回复 | 不注入完整页面规则，不修改工程 |

### S6：处理大页面和模型输出限制

分清输入超限、思考消耗、正文输出截断与来源 CSS 体积；不统一解释为“加 max_tokens”。输出预算依据 Provider/模型实际能力和设置，不写死 8192 或无限增加。

普通生成使用已存在的有界续写；复杂同页可采用公共骨架＋2～6 区块，区块独立生成、程序合并；大页面重塑使用有限 JSON 补丁/变量绑定，不强制回传整页 HTML。改变产品页面数量的拆页必须由用户确认。

合并后完整执行原验收，不交付半页、不凭空补闭合标签掩盖缺失。续写、分区、修复分别记账，不能叠加为无限重试。显示阶段、区块进度、正文/思考量、预算、最后活动、超时/取消及可恢复条件。

检查点当前仅在会话内存在；本轮不默认新增跨重启自动续写。基线、模型或主题改变时旧检查点失效。

### S7：分层验证并处理失败

顺序：输出完整与安全 → 任务/内容与节点合同 → 样式/资源/实体 → 参考设备实际渲染 → 来源/规则回执与当前状态一致。

验证结果分别显示阻断、警告、未验证和人工审阅。主观审美建议不伪装成硬错误；图片/渐变对比度不能直接套纯色算法；未执行的检查不标通过。

必需检查未执行或不可用时不允许采纳；建议类未验证只披露局限。检查是否必需由工作流注册表及已确认合同决定，不由检索规则或模型临时决定。语义内容必须区分可测事实与人工判断，不能把一次模型自评当成验收证据。

一次候选最多一次自动受控修复，修复只针对发现项及授权范围，之后重新执行相关门禁与整体完整性。仍失败则保留安全草稿、具体节点和原因，原页不应用。用户再次明确启动修复属于新任务，不借此重置旧任务的计数。

### S8：展示候选、采纳与撤销

展示原页与候选、变更摘要、规则来源、检查证据及局限；对比时降低其它页面视觉干扰。已有替换原版、两版保留、保留原版行为保持一致。

按钮有明确忙碌/禁用原因，不能点击后无反馈。采纳前再次核对基线、主题、来源、规则包、保护和当前证据。过期则重新验证，不直接覆盖。采纳走 History，保存副本、组件和 Token 时保持同一作用域事务语义。

原页/授权变化需重新冻结任务，不能仅复验旧候选后覆盖新原页。无关目录升级不使冻结任务失效；检查器/渲染环境变化可仅重验相关证据。History 的内存事务不等于所有侧车跨文件原子写入：沿用现有仓储恢复协议，保存失败保留可重试状态并明确告知，不报告已持久化成功。

### S9：保存、重开、导出与经验归档

使用现有 `.aidesign` 仓储，页面路径按 ID 规范化；资产真实落盘，候选/交付证据及规则回执按现有侧车机制保存。重开后不能拿历史通过证据直接解锁当前页面。

画布、HTML 和 PNG 使用同一业务内容、Token、CSS 和视口解析来源；顶部壳层按既有导出合同区分。HTML 导出不带系统状态/默认微信导航；图片包含模拟顶部；自定义业务导航属于内容的情况按当前开关处理。

用户采纳/拒绝及返修原因可供本地评估；默认不自动改主题、不自动收录私有页面、不上传训练，也不将一次采纳推广为全局审美规则。

## 5. 用户可见入口

- 项目设置：继续展示工程路径、设备与参考设备、导航策略；不新增档位切换。
- 项目文档：事实、推断和人工决定可查看编辑；保存沿用 History。
- 设计系统/完整主题编辑器：复用已有预设、自定义主题和页面风格提取入口；提取与应用分开。
- 对话：正常输入不增加必经向导；以可折叠“本次设计依据”显示场景、所用规则、来源和回退。
- 宽泛优化卡片：保留选择＋补充文字，明确执行范围。
- 候选证据面板：来源/版本、检查、未验证和过期状态集中呈现。
- 批量重塑：预检不等于视觉合格；队列及试跑进度可见、可停止。

## 6. 成功定义

需要同时证明：流程遵守授权；场景规则确实相关并实际注入；内容和工程一致性未退化；生成页经实际渲染；采纳可追溯/撤销；对照实验显示质量收益。规则数量、测试数量和漂亮示例都不能单独证明目标达成。

## 实施合同补充：元素 JSON（2026-10-30）

明确元素局部修改允许在内部试点参数下，以同预算场景建议替换既有可替换组件参考窗口；不改变用户交互或 JSON 操作范围。实际指令必须与冻结合同相同，失败/取消/过期不得发布候选。对象回执只证明应用输入调用，不能代替安全与渲染验收；默认启用依然受 M5 门槛约束。
