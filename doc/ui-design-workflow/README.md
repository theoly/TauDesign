## 一条主线

需求与工程事实 → 任务分流及授权 → 场景判断与规则检索 → 设计简表与内容合同 → 原生组件/Token 实现 → 完整性及实际渲染检查 → 一次受控修复 → 候选采纳 → 保存、重开、导出与证据归档。

流程阶段是内部职责划分，不是要求用户每次手动经历多轮确认。明确局部修改直接执行；只有宽泛优化、范围扩大和现有交互要求确认的任务才展示选择。

2026-10-30 流程复核：上述主线的“设计简表与内容合同”尚未完整实现为用户任务、具体功能、必需信息、操作和状态的结构化规划。普通单页主要依赖提示词推断；当前简表数据结构和渲染门禁不能等同于业务功能完整。建议在布局/视觉之前补业务简表、功能修改差量及逐项覆盖，保留现有执行与存储框架，详见[功能优先审计](./function-first-audit.md)。本段记录建议，不表示新规划能力已上线。
