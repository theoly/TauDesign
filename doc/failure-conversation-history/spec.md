# 分区图片证据与失败会话存档

2026-11-12。用户要求修复“当前请求没有携带匹配的图片解析证据”，并保存失败对话历史。

## 根因

只读核对失败任务：7个功能组自动采用SectionedPatch，原请求和解析均有效，首次reference-input回执已通过；布局子请求只重建原需求与布局JSON，遗漏图片证据，在实际发送前再次校验失败。复用规划时预算0次与该分支一致。不能关闭来源校验或假装已发送。

主对话的error/no_html/quality/guard早退与catch、分析/多页/结构化修改失败绕过成功分支的JSONL追加；恢复时空助手文本还可能显示成功默认文案。

## 实现边界

- 布局子请求显式接收冻结的ReferenceEvidence，构造实际消息时补入同一解析，不读历史图片、不重发二进制、不扩大来源或区域权限；保留每次发送前的原校验。
- 失败/拒绝/取消的已提交对话存入现有按月append-only JSONL：原用户要求、附件相对路径、错误、阶段/预算摘要、模型/终态、可验证历史规划；不存凭据、原始响应/图片编码，也不赋予恢复执行权。
- 活动尝试按冻结工程与唯一attempt身份存档；重试是新尝试，严格模式/重渲染不重复写。同一任务的实时存档与旧档案补入使用同一turnId并幂等。
- 重开显示失败状态、只读诊断与“重新使用该需求”；该动作仅填入输入框，不调用模型、不启用引用、不自动附图或采纳。
- 可从现有任务索引补入最近可验证、有错误摘要的blocked/cancelled任务（索引既有限额40项，更多历史仍在任务档案）；坏文件不阻止读取会话，不导入已完成/已交付任务。先显示已有会话，再补入失败任务；旧任务回溯不修改原失败档案。
- 写盘失败明确提示；图片存档失败仍保存文字并标记附件缺失。失败记录不被旧分片压缩抹掉，损坏单行不影响其他行。

只做本机与合成数据验证，不将用户工程发送给外部模型。现有原页、候选、History和导出媒体规则保持。
