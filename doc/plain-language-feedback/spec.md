# AI反馈提示的通俗化

日期：2026-11-14。用户指出“SkeletonMainAtomic：完整main已取得，仍须全部交付检查。”包含内部术语，要求检查类似提示并优化。

## 目标与范围

覆盖AI生成/分区/续写进度、警告、系统错误、通信摘要、用量卡片、历史失败、候选修复记录、AI服务容量设置、欢迎语及批量风格调整进度。正常界面应说明当前进度、问题影响和用户下一步，而不是暴露执行模式、协议、数据结构名称。

- 四种内部生成模式不变，展示为直接生成、先规划后生成、分区域生成、复制后局部修改。
- 常规成功步骤放在实时进度，不长期作为黄色警告显示；保留真正警告和错误。
- 旧会话提示也能显示通俗版本；只格式化程序生成的通知，不改写用户要求、AI正文、HTML/CSS、模型提示词或持久化的诊断原文。
- 协议结束原因、步骤ID显示中文含义；未知值不猜测业务含义，仍可在技术详情中查看原值。
- 用量计量保持真实单位，不把Token当字数或费用；额度和请求次数准确保留。
- 源码编辑、文件格式选择、模型名称、详细诊断中的必要术语保留。技术信息需展开查看，禁止改变授权、取消、重试、校验或History行为。

## 初步审计

| 位置 | 问题 | 优化 |
|---|---|---|
| 页面主体完成提示 | 内部模式、main、交付门禁 | 页面内容已生成，正在检查内容与布局；常规步骤进入进度 |
| 分区进度 | 补丁、归属回执、父预算 | 区域安排、核对原页内容、本轮额度 |
| 续写 | 原生续写、HTML续写、tokens | 继续生成、接着完成页面，用量单位 |
| 通信摘要 | Provider ID、finish reason、stage ID、JSON | 模型名称、中文阶段/结束说明，原值收进技术详情 |
| 预算摘要 | 父任务、申请输出、Token缺少解释 | 本轮请求额度、AI回复长度计量，明确不是字符数/费用 |
| 系统错误/旧警告 | DOM/CSS/基线/指纹/合同 | 页面结构/样式/原版本/校验信息/本轮要求；保留技术原文 |
| 风格调整 | !important、HTML、实例下发 | 手动设置、页面内容、同步使用该组件的页面 |

## 验收

默认展示不出现目标内部模式名；历史提示可读；关键数字、模型和错误后果准确；技术原文可查；程序数据与操作行为不变。定向测试与UI验证后运行全量测试、类型检查和生产构建，归档test.md。

## 新增提示的约定

新提示优先直接描述用户能理解的进度、结果和下一步；不把内部模式名、接口字段或数据结构名拼进普通提示。已保存的历史消息通过展示层兼容，技术原文在“技术详情”中保留。不要把“AI已回复”等同于生成完成或检查通过，不把Token等同于字符数或费用。
