# TauDesign UI 设计指导

适用于生成新页面、按参考图设计、页面修改和质感润色。指导按用户提供的 Refactoring UI v1.0.1 中相关原则整理，结合 TauDesign 的 Token、设备档位、导航和局部修改约束。设计原则用于选择方案，实际交付还需源代码检查和设备渲染验证。

2026-10-29 整合：[完整流程与实施方案](../ui-design-workflow/README.md)补充任务分流、规则检索、来源回执、验收与分阶段任务。本页保留为实用示例；整合方案中的新增功能仍待实施。

## 1. 先确定内容与操作

先说明用户来这里要完成什么、最重要的信息是什么、下一步是什么，再选择容器和装饰。例如充值页应先安排余额、套餐、支付操作及说明，不能先铺满卡片再塞入文案。

同一区域的主要操作通常只保留一个视觉焦点；次操作降低填充和字重。重复操作的列表可保留一致的按钮，不机械要求整页只出现一个主按钮。危险操作保留危险语义，但不必在所有上下文里都是最大的彩色按钮。

新建页面可按业务要求呈现空、错误、加载等状态。空状态应说明当前情况并提供适合的下一步。修改旧页时，仅处理用户授权内容，不因规则主动补状态、删除节点或重新组织全部内容。

## 2. 层级与排版

用字号、字重、前景对比共同表达主次。重要标题可用 `.text-xl` / `.text-2xl` 和 `.font-semibold` / `.font-bold`；正文以设备指导为准：当前移动端 `.text-md`，PC `.text-sm`。辅助信息优先降低字重或用可读的次级前景，不将必读说明一律缩成 `.text-xs`。

正文自然换行，长段落可用 `.leading-relaxed`。标题和单行按钮使用基座行高；不写白名单不存在的行高和字距类。中文不直接套用英文的字符行长或大写字母追踪间距。

相邻的金额与单位、数字与后缀按文字基线对齐；图标、头像、按钮的内部对齐仍按盒子居中。长正文通常左对齐，数值列右对齐，短按钮标签居中。不要用位移或负边距制造视觉对齐。

```html
<div class="row items-baseline gap-1">
  <strong class="text-2xl font-semibold">128</strong>
  <span class="text-sm text-secondary">积分</span>
</div>
```

语义标题和表单标签不因“弱化视觉”被移除；标题等级不等于必须使用浏览器默认的大字号。

## 3. 分组、宽度与长内容

组内间距小于组间间距，让用户一眼判断标签属于哪个字段、说明属于哪个区块。标题距下方正文应比距前一组内容更近。间距取现有 Token 等级，并遵守设备档位，避免每个方向都使用同一个 gap。

PC 内容按最大宽度容器组织，移动端主要内容保持单列；不要等比缩小 PC 页面。卡片的列数应服从实际内容宽度；减少列数或让整组换行，不能把正文压成逐字竖列。

长文案应占独立内容宽度，配合 `.min-w-0` 和必要的 `.break-words`；按钮、姓名和短标签分别遵守已有组件合同。长文本卡片用纵向结构承载正文，再安排操作区，不能给正文固定高度后裁掉文字。用户指定文案完整保留。

```html
<section class="card p-4 col gap-4">
  <div class="col gap-2">
    <label for="contact" class="text-sm font-medium">联系人</label>
    <input id="contact" class="input" placeholder="请输入姓名" />
  </div>
  <p class="text-sm text-secondary leading-relaxed">仅用于本次预约联系。</p>
</section>
```

上例仅说明分组关系；真实页面的移动端输入需追加设备要求的触控样式。

## 4. 配色与渐变

先使用当前设计系统中页面、卡片、分组和操作的颜色角色。项目已配置的渐变可以保留；禁止通用“审美规则”把它强制清成中性色。品牌色用于焦点和选中状态，背景装饰不能掩盖业务内容。

文字前景必须与实际承载面匹配。彩色背景不机械套浅灰字，不能靠降低整个容器透明度弱化说明。低优先级状态可使用浅语义底和可读的语义文字；状态还应有文字、图标或形状提示，不能只靠红绿区分。

渐变、图片、半透明叠层要按文字覆盖区域检查可读性；必要时用项目的遮罩或实底承载文字。纯色对比度检查不代表复杂背景已经通过视觉验证。亮色/暗色模式分别审阅。

## 5. 边框、深度与图像

优先考虑留白和承载面区分分组；确需边界时使用项目边框或轻阴影。不要给每层嵌套容器同时添加边框、阴影和渐变。输入边界、选中提示和键盘焦点仍须清晰。

阴影表达距离：平面信息可无阴影或轻阴影，菜单和弹窗比普通内容更高。使用项目阴影 Token，避免自造硬编码阴影和互相矛盾的光源。

图标保持设计尺寸及一致笔画，需要占据较大面积时增大图标容器；不能将小图标放大数倍填满卡片。通知角标仍附着在图标右上，预留空间、不遮主图标；不改为图标和角标并排。

图片按用途选择比例并保护主体，裁切应发生在媒体容器，避免拉伸。为加载和失败保留适当底色/占位。表单、正文和按钮不要跟随媒体裁切。相关样式只能使用白名单，或通过工程已支持的样式来源合同实现。

## 6. 修改与交付审阅顺序

1. 确认当前任务、设备、主题、参考来源和允许改动范围。
2. 检查主操作、核心内容、分组关系和正文宽度，再调整颜色和装饰。
3. 按参考设备渲染，检查长姓名、URL、多按钮、图片主体、空状态和吸底区域是否遮挡或溢出。
4. 核对文案、节点和手动保护内容；按既有校验合同处理阻断项，不以“符合指导”替代真实检查。
5. 展示候选与原页对比，通过既有采纳与 History 管道应用结果。

## 维护位置

- `src/services/ai/craft/`：共享工艺指导，新建/修改共用；润色经统一 PromptBuilder 接入。
- `src/services/ai/aestheticRules.ts`：设备约束、布局和状态合同。
- `src/styles/base.css` 及设备切片：类名权威来源，禁止手写平行白名单。
- `test/ui_design_guidance.test.ts`：两档位类名、各执行入口和保护合同检查。
- `test/prompt_contract.test.ts`：提示词预算；新增规则先去重，不能无限追加。

这些规则提升约束完整性，不承诺每次模型输出都自动满足所有审美要求。实际生成质量仍由候选验证和人工审阅共同确认。
