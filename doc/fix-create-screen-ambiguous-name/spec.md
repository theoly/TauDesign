# 新建页面误报同名页面引用歧义修复规范 (Fix Create Screen Ambiguous Name)

## 1. 背景与问题定义 (Background & Problem)
用户在 Chat 输入框发送长篇 PRD/需求说明，最后一句明确要求新建页面：
例如：`按上述要求新建页面"推荐购买引导页"`，或直接要求 `新建页面"完善资料弹窗"`。
当画布上碰巧存在同名画框（例如两个重名的「完善资料弹窗」），TauDesign 会意外中断并报错：
> "无法确定本轮操作对应的页面。存在同名页面：完善资料弹窗。请使用 @页面ID 或明确启用目标页引用。为避免误改到不相干的页面，本次未做任何改动。请任选一种方式指明目标：1. 在输入框下方点亮【引用画框】开关；2. 在诉求里用 @画框名 指明目标；3. 先在画布上点选要修改的画框。"

### 根因分析
1. **`screenReferenceResolver` bare-name 范围越界**：
   - 当 prompt 中没有「参考/基于/...」前导词（`cue < 0`）时，`createAfter` 为 `-1`，`end` 错误回退为 `text.length`；
   - 导致在明确新建动词（`新建|创建|生成|新增|设计一个|做一个`）之后声明的新页面标题（如 `新建页面"完善资料弹窗"`），以及前文业务需求中顺带提及的名词（如“跳转完善资料弹窗”），全被当成候选画框抓取；
   - 若命中多个同名画框，直接打上 `ambiguousNames`。
2. **`generationTargetResolver` 过早拦截新建意图**：
   - 在识别用户口令意图（`classifyCommand`）之前，无条件检查 `resolution.ambiguousNames`；
   - 只要存在 `ambiguousNames`，不论用户是否在「明确新建画框」（`explicit_create`），直接一刀切判定为 `needs_reference`；
   - 新建画框根本不会覆盖任何既有画框，却报出“为避免误改到不相干的页面本次未做任何改动”，违背了 BR-GT-05（无引用+新建一律新建）的基本原则。

## 2. 范围边界 (Scope)
- **In Scope**：
  1. 优化 `screenReferenceResolver.ts`：
     - 若存在新建动词，所有在新建动词之后的裸词一律不得作为画框引用源（那是新页名或新页需求）；
     - 若无显式参考语义词（`参考|基于|仿照|照着|沿用|复用|借鉴|根据` 等），且用户是在发起新建指令，长文本正文中的裸词不得作为参考源；
     - 显式 `@mention` 与显式引号 `参考“xxx”` 依然全量保持严格匹配与歧义检测；
  2. 优化 `generationTargetResolver.ts`：
     - 口令分类为 `explicit_create` 时，若未显式指定歧义画框为参考源（未用 `@mention` 且未以 `参考...` 指定），不得拦截为 `needs_reference`，必须放行 `create_screen`；
     - 若用户明确要求新建一个与现有画框同名的画框（例如 `新建页面"完善资料弹窗"`），正常执行新建，不报歧义；
     - 若用户显式要求参考同名画框（例如 `参考完善资料弹窗，新建...` 或 `参考 @完善资料弹窗，新建...`），保持既有行为拦截并提示指定 `@页面ID`。
- **Out of Scope**：
  - 不改变修改现有页面（`modify_screen`）的同名画框防护机制；
  - 不改变已有的主题调节与提问路由。

## 3. 业务规则与契约 (Business Rules)
- **BR-CS-01**：新建动词之后出现的画框名称属于即将创建的新页面标题，不得被解析为现有画框的引用。
- **BR-CS-02**：无参考动词的新建诉求，正文中的裸画框名不构成画框引用。
- **BR-CS-03**：明确新建（`explicit_create`）在未显式 `@` 或显式参考同名画框时，必须返回 `action: 'create_screen'`，严禁阻断为 `needs_reference`。
- **BR-CS-04**：显式引用（`@同名画框` 或 `参考“同名画框”`）在新建时若存在同名歧义，依然保持拦截并引导指定 `@页面ID`，确保参考基准唯一。
